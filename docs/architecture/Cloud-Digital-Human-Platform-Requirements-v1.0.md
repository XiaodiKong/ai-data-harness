# 云端数字人平台能力要求与验收清单

**版本：** v1.0 · 评审草案

**日期：** 2026-10-09

**适用对象：** 云端数字人平台团队、AI-Data 团队、现有数据平台团队

**关联方案：** [AI-Data 技术方案 v1.1](./AI-Data-Harness-Technical-Design-v1.1.md)；[v1.0 历史方案](./AI-Data-Harness-Technical-Design-v1.0.md)

> 目标：用户通过 CLI 管理一个研发事项，云端数字人承载从需求、开发、验证到交付的完整过程。云端平台提供通用运行与治理机制，AI-Data 提供数据研发知识、方法、流程和验收规则，现有数据平台继续执行计算、发布与调度。

本文用于能力盘点、接口评审和联合验收，不代表云端平台已经具备这些能力。所有接口字段和 CLI 操作名称均为拟议语义，须与平台团队确认实际映射。

## 1. 已确认事实、建设目标与待核验项

### 1.1 本轮确认的信息

| 编号 | 信息类型 | 用户确认的信息 | 可以据此做出的设计决定 |
|---|---|---|---|
| F-01 | 现状 | 通过 CLI 访问部署在云端的数字人 | 首个客户端入口采用 CLI，复用现有接入方式 |
| F-02 | 现状 | 数字人可自主查表、读代码、调用工具、测试和修改 | 复用现有 Agent 任务内执行能力 |
| F-03 | 现状 | 可以优化数字人的知识库等外挂信息 | AI-Data 可以持续改进专业知识和方法 |
| F-04 | 建设目标 | 用户希望完整研发过程也集成到数字人中 | 事项管理和跨阶段编排以云端承载为目标 |

F-02 说明已有自主执行能力，不等于已确认任务持久化、生产权限、可靠恢复或交付验收能力。F-03 不等于已确认支持特定厂商的 Skill 或 Plugin 格式。

### 1.2 目标要求

- 关闭 CLI 后，已受理事项可在云端继续执行或等待事件。
- 研发事项跨天、跨会话持续存在，代码、阶段结果与决策可追溯。
- 阶段推进由持久化状态和确定性规则控制，数字人负责阶段内分析与操作。
- 人工确认、测试、发布和数据验收关联到明确的内容版本。
- 外部操作结果不明确时进入核实流程，恢复时区分已落盘状态和未完成调用。
- AI-Data 专业能力可配置、可版本化、可回归验证，可从平台导出关键记录。

### 1.3 尚未确认

现有 CLI 协议及机器输出、后台运行、事项 ID、工作流持久化、事件订阅、产物存储、隔离环境、授权机制、外部操作查询与去重、并发控制、能力包格式、审计及预算均待核验。

原方案描述的现有 MCP、发布与调度基础继续作为接入背景；每个接口的实际版本、权限、状态查询和副作用语义仍需联调证明。本文不据此承诺现有接口具备事务性或幂等性。

## 2. 三方职责与状态归属

| 领域 | 云端平台：通用机制 | AI-Data：业务配置 | 现有数据平台：实际执行 |
|---|---|---|---|
| 事项与流程 | 事项记录、工作流、阶段状态、恢复与等待 | 需求契约、研发阶段、进入与完成条件 | 返回资产和运行事实 |
| 数字人能力 | 执行环境、工具接入、能力版本装载 | 口径、Skill、模板、适配规则、回归案例 | 提供元数据、代码、血缘等接口 |
| 开发与测试 | 隔离工作区、版本化产物、校验器执行 | SQL 规范、测试设计、验收阈值 | 提供受控测试计算与结果查询 |
| 权限与确认 | 身份校验、策略执行、授权记录、凭据隔离 | 风险分类、需确认事项、允许的操作范围 | 对自身资产和操作执行最终权限校验 |
| 发布与重跑 | 操作账本、去重、状态核实、结果关联 | 发布范围、业务分区、恢复计划 | 发布代码、执行调度、报告实际状态 |
| 交付与运营 | 证据保管、日志审计、预算、导出 | 业务验收规则、效果评估与知识改进 | 提供已发布版本及数据结果证据 |

逻辑职责应清楚，不要求分别部署独立服务。可复用云端已有组件，也可先在同一服务内实现这些边界。

权威状态归属：需求与修订属于事项记录；阶段状态属于工作流；外部操作意图与核实记录属于操作账本；资产版本和运行事实属于现有数据平台；知识库不作为上述运行状态的唯一存储。

## 3. 核心对象与身份要求

| 对象 | 标识与版本 | 必须区分的含义 |
|---|---|---|
| DigitalHumanDefinition | `digital_human_id`、不可变 `definition_version` | 专业执行者的配置，引用知识、能力包、工具契约和策略版本 |
| ChangeSet | 永久 `changeset_id` | 一件从需求到交付的研发事项；保留历次修订和运行 |
| ChangeSetRevision | `changeset_id` + `revision`，或等价的 `revision_id`；内容摘要 | 不可变的需求、验收规则、代码基线、变更范围和能力依赖输入 |
| WorkflowRun | `workflow_run_id` | 按明确流程版本推进某次事项修订的执行过程 |
| StageRun | `stage_run_id`、阶段、尝试序号 | 某个阶段的一次执行；重试或重做保留新旧关联 |
| AgentSession | `session_id`、所属阶段运行 | 一段 Agent 上下文；可被清空或重建，不能代替事项身份 |
| ExternalOperation | `operation_id`、业务幂等键、外部任务 ID | 一次具有明确意图的外部动作；网络重试关联原操作 |
| Artifact / Evidence | `artifact_id`、内容摘要、来源运行 | 不可变代码、报告或结果证据，带版本和完整性信息 |
| Decision / Authorization | `decision_id`、真实身份、绑定范围、有效期 | 对指定修订、计划或产物的决定及授权依据 |

关键关系与约束：

1. 一个数字人定义可服务多个事项；一个事项有多次修订和运行。
2. 一个工作流运行包含多个阶段运行；阶段内可建立多个 Agent 会话。
3. 进程恢复不自动创建新的业务操作；执行重试不得通过更换操作 ID 绕过去重。
4. 需求、代码基线或验收范围变化时创建新修订，记录受影响证据与决策的失效关系。
5. 输入和依赖版本在运行启动时锁定；采用新版本需显式迁移或创建新运行。
6. 工作流重跑和恢复的标识规则由接口契约说明，均须保留因果关联与历史。
7. 暂停、取消、恢复请求携带期望修订或状态版本，避免旧客户端覆盖新状态。

## 4. 通用能力要求

优先级含义：**P0** 为沙箱闭环必需；**P1** 为接入生产前必需；**P2** 为扩展与运营增强。已有能力可直接验收复用。P0 使用只读或沙箱身份；生产能力未通过 P1 验收前不得开放生产副作用。

### CAP-01 事项与修订管理 · P0

- 创建、读取、修订和归档事项；保存目标、验收条件、资产范围、负责人和阻塞原因。
- 提供稳定 ID、不可变修订与并发版本检查，记录每次状态变化的来源和时间。
- **通过证据：** CLI 重连后可查询原事项；需求修订前后内容及受影响运行可对照。

### CAP-02 持久化工作流与恢复 · P0

- 后台推进阶段，保存输入、已确认输出、等待条件、重试策略和超时状态。
- 区分完成、失败、等待、暂停、取消请求中、已取消等语义，允许流程定义进一步细分。
- 恢复已落盘的状态；对未确认完成的工具调用按操作类型检查结果，不能一律视为未执行。
- 明确状态和产物的备份、保留及恢复目标；生产启用前演练灾备恢复后对在途外部操作的核实。
- **通过证据：** 关闭客户端、终止工作进程后，原事项能恢复到可解释的阶段且历史不丢失。

### CAP-03 外部事件与人工参与 · P0；生产授权为 P1

- 持久化接收确认、驳回、补充信息、调度结果等事件，支持事件 ID 去重和关联校验。
- 明确处理重复、迟到、乱序、过期事件及等待超时，未经验证的外部回调不能推进阶段。
- 审批绑定事项修订、计划或产物摘要、环境和操作范围；代码变化后重新检查其有效性。
- **通过证据：** 跨天确认可恢复任务；重复确认不重复推进；旧版本批准不能放行新版本。

### CAP-04 隔离工作空间与版本化产物 · P0

- 为任务准备受控工作区，锁定代码基线、依赖、工具配置和能力版本，隔离不同任务的数据与凭据。
- 持久化代码差异、日志、测试报告和引用关系，支持摘要校验、访问控制及约定保留期。
- 工作区可重建，明确临时文件和正式产物边界；恢复运行不得依赖某台机器的未保存目录。
- **通过证据：** 销毁原工作进程后能恢复代码与报告；不同任务不能读取未授权产物。

### CAP-05 流程、验证器与策略扩展点 · P0

- 支持注册流程模板、阶段输入输出契约、确定性验证器、进入条件和完成条件。
- 区分 Agent 提出的候选结论与验证器作出的校验结果，校验失败有明确原因和可执行后续步骤。
- 扩展程序的身份、网络、资源和副作用范围受控，脚本退出成功不自动等于业务验收成功。
- **通过证据：** AI-Data 可配置“测试报告对应当前代码”规则，并拦截不匹配报告。

### CAP-06 知识、Skill 与能力包生命周期 · P0；规模分发为 P2

- 为知识快照、Skill、脚本、模板、工具契约记录版本、来源、适用范围和兼容关系。
- 支持按任务锁定版本、禁用问题版本、回退和回归验证；知识更新不静默改变在途任务。
- 版本锁定不绕过撤销：权限、被禁用能力及企业强制策略在后续动作前复核；受影响事项进入明确等待或处置状态。
- Plugin 可作为能力包形式，实际格式以云端契约为准，不预设兼容所有厂商插件。
- **通过证据：** 同一案例能关联更新前后的依赖版本与评测结果；旧运行的依赖仍可识别。

### CAP-07 身份、权限与生产授权 · P0 基础隔离；P1 生产控制

- 区分发起人、Agent 执行身份、审核人和工具服务身份，贯穿租户、资产及环境边界。
- 凭据由平台托管和注入，按最小范围授权；确定性执行层校验权限，提示词不作为授权凭据。
- 生产授权绑定操作类型、资产、分区、版本、有效期和必要的前置条件，调用时再次校验。
- **通过证据：** 沙箱任务无生产写权限；伪造身份、过期授权和范围外操作均被拒绝并留痕。

### CAP-08 外部操作账本、去重与核实 · P1

- 发布、重跑、建表等动作在调用前记录操作意图、请求摘要、幂等键及预期前置状态。
- 区分未发起、执行中、成功、失败、结果未知，保存外部任务 ID 和权威状态查询结果。
- 重试复用业务幂等键；同键异参拒绝；超时后先核实，无法核实则阻塞并交人工处理。
- **通过证据：** 模拟发布成功但响应丢失后，能确认原结果且不盲目重复发布。

### CAP-09 独立验收与交付判定 · P0 沙箱；P1 生产证据

- 验收规则来自已确认需求，由受控验证器执行，必要时由独立验收责任人基于证据复核；开发 Agent 不能自行修改规则并判定通过，另一模型的意见也不能替代实际测试结果。
- 证据绑定事项修订、代码与配置摘要、数据范围及输入快照或水位、环境、规则版本和执行时间；缺失或失效证据阻止完成。
- 生产交付还需核实已发布版本、调度运行和目标数据结果，模型总结只作说明。
- **通过证据：** SQL 可运行但窗口边界错误时，验收失败；旧报告不能证明新代码通过。

### CAP-10 并发、冲突与资源预算 · P0 任务预算；P1 生产冲突

- 为任务配置时间、调用量、计算和修复次数等预算，超限后停止新步骤并报告在途操作。
- 对资产和业务分区维护读写范围；发布前检查版本漂移与冲突，采用锁或乐观校验等适当机制。
- 对超时或失去租约的旧执行者，在实际写入路径落实拒绝或等效保护；仅在本地标记过期不能证明远端写入已被阻止。
- 多个任务可排队、并行或等待，冲突不能靠数字人在聊天中自行协调。
- **通过证据：** 两个事项修改同一节点时，过期基线被阻断；预算耗尽后不继续自动修复。

### CAP-11 审计、事件查询与可导出记录 · P0

- 记录事项、工作流、阶段、会话、工具调用、外部操作和产物之间的关联及状态变化。
- 提供结构化事件查询、游标续读、状态快照及受权限控制的导出，说明保留期和事件缺口处理。
- 日志适当脱敏，导出不包含可复用凭据；观测日志不能替代事项状态与操作账本。
- **通过证据：** CLI 断连后可补读事件；导出记录能解释一次交付使用了哪些版本、证据和决策。

### CAP-12 暂停、取消、超时与恢复操作 · P0；外部生产取消为 P1

- 暂停阻止后续步骤，继续前重检输入和权限；取消请求与最终取消状态分开表示。
- 对已提交外部操作查询实际状态，支持取消时调用取消接口，不支持时说明继续运行或等待核实。
- 取消不等于回滚；补偿、数据恢复和再次执行使用明确计划及独立授权，不假定具有原子撤销能力。
- **通过证据：** 运行中取消时能准确报告已完成、已停止、仍在执行及需人工处理的操作。

## 5. CLI 与事件的拟议契约

### 5.1 操作语义

下表是对 CLI 的功能要求，不是可复制运行的实际命令。平台团队填写现有命令或缺口，CLI 背后不强制采用特定通信协议。

| 拟议操作 | 必需行为 | 关键输入或输出 |
|---|---|---|
| 提交事项 | 校验后受理，返回可持续查询的身份 | 请求幂等键、数字人版本、需求；事项 ID、修订 ID、运行 ID |
| 查询状态 | 返回服务端状态及其来源与时效；执行前读取必要的权威状态 | 阶段、状态版本、更新时间、阻塞原因、在途操作、下一步 |
| 跟踪事件 | 断连后可按游标续读 | 事件 ID、游标、关联 ID、发生时间、载荷版本 |
| 补充信息或修订需求 | 补充明确的待回答项；改变已确认输入时创建新修订并计算影响 | 待回答项 ID、期望修订、补充或变更内容、失效证据和需重做阶段 |
| 确认或驳回 | 校验真实身份和对象版本 | 决策 ID、修订、产物摘要、授权范围、有效期 |
| 列出或获取产物 | 权限校验后返回产物及完整性信息 | 产物 ID、摘要、来源运行、下载或读取方式 |
| 暂停、继续、取消 | 返回请求受理及实际状态 | 请求 ID、期望状态版本、在途操作及后续核实方式 |
| 导出事项 | 输出可读记录和机器结构记录 | 修订、事件、版本引用、决策、证据及外部操作关联 |

### 5.2 机器调用约束

- 输出支持稳定结构及 `schema_version`，业务结果、诊断日志和流式事件有明确边界。
- 同一提交幂等键和相同输入返回原事项；同键不同输入返回冲突，不悄悄新建或覆盖。
- 连接断开、客户端超时、命令退出、任务失败分别表达；客户端退出不隐含取消云端任务。
- 受理成功不等于执行成功；退出码与结构化错误须区分校验失败、权限拒绝、冲突和临时故障。
- 提交响应丢失时，客户端可按请求幂等键查询或安全重试，找到原事项。
- 事件包含 `event_id`、`changeset_id`、`workflow_run_id`、状态版本及必要的关联 ID。
- 允许事件重复投递，消费者按 ID 去重；状态推进仍由服务端检查当前版本和前置条件。
- 游标过期或事件保留期不足时明确报告缺口，允许获取快照并建立新的读取起点。
- 对自动化调用提供非交互模式；需要人工决定时返回等待状态，不把默认输入当作批准。
- 导出格式应保留领域对象与证据引用；不要求导出模型内部推理或跨引擎搬运完整聊天上下文。

### 5.3 不作出的承诺

不承诺分布式外部操作具有普遍的 exactly-once 语义。平台通过稳定意图、幂等、版本条件、结果核实和必要的人工处理控制重复与遗漏；具体保证取决于目标系统接口。

恢复只能使用已经持久化的状态和可查询的外部事实。对崩溃前尚未完成记录的调用，必须判断它是否已经产生作用；既不能直接宣告成功，也不能因为本地缺少结果就直接重发。

## 6. 联合验收场景

### ACC-01 跨天研发交付闭环

测试需求：“客户画像新增近 90 天逾期次数”。双方先确认测试资产、SQL 方言、窗口和去重口径、客户粒度、空值语义、旧指标回归规则及发布权限。

| 步骤 | 执行动作 | 通过证据 |
|---|---|---|
| 1 | 通过 CLI 提交指定需求与验收规则 | 返回稳定事项 ID、修订、数字人和流程版本 |
| 2 | 关闭 CLI，让云端查资产、开发并测试 | 后台运行记录、代码差异、测试数据范围和报告摘要 |
| 3 | 开发完成后进入等待确认状态 | 明确等待对象、产物版本和阻塞原因；等待时无需持续占用 Agent 会话 |
| 4 | 在等待期间终止并重建执行工作进程 | 原事项仍可查询；产物存在；工作流从已保存等待状态恢复 |
| 5 | 次日重新连接 CLI，查询并确认指定版本 | 事件续读、真实审核身份、有效决定及产物绑定记录 |
| 6 | 按已授权范围发布并触发运行 | 操作账本、外部任务 ID、权威版本及运行状态 |
| 7 | 按预定规则独立核验目标数据和旧指标 | 关联代码、环境、分区和规则版本的数据验收证据 |
| 8 | 标记交付完成并导出记录 | 需求、代码、测试、批准、发布、调度、数据验收可相互追溯 |

P0 阶段将步骤 6 替换为沙箱发布或模拟外部操作，交付状态明确标记为“沙箱验证完成”；生产交付需通过对应 P1 能力与接口验收。

### ACC-02 至 ACC-13 故障与边界验收

| 编号 | 注入方式与执行步骤 | 通过条件与证据 |
|---|---|---|
| ACC-02 | 提交已受理时丢弃响应，随后用相同幂等键重试；再用同键改动输入 | 前者返回原事项；后者明确冲突；没有多建事项 |
| ACC-03 | 工具调用前、调用中及结果落盘后分别中断工作进程 | 已保存结果不丢失；未完成调用按类型核实；恢复日志说明判断依据 |
| ACC-04 | 发布实际成功但丢弃响应，再重启执行进程 | 操作先进入结果未知或核实中；查询外部事实后关联原发布，不盲目再次提交 |
| ACC-05 | 外部操作结果未知且查询服务不可用 | 停止依赖该结果的步骤，暴露阻塞与人工处理入口，不假定成功或失败 |
| ACC-06 | 对同一版本重复批准；批准后修改代码；再送达旧批准 | 重复事件不重复推进；新代码使相关批准失效；旧批准无法放行 |
| ACC-07 | 两个事项从同一基线修改同一节点，先后请求发布 | 后提交者检测到版本漂移或锁冲突，重做影响分析及必要验证后才能继续 |
| ACC-08 | 调度运行中请求取消，分别测试可取消和不可取消任务 | 区分取消请求与已取消；列明仍在执行操作，随后核实其最终状态 |
| ACC-09 | 用新代码搭配旧报告；让可运行 SQL 违反窗口边界规则 | 证据版本校验和业务验收分别失败，事项不能标记交付完成 |
| ACC-10 | 耗尽修复预算；尝试跨任务读产物及使用过期生产授权 | 停止新尝试并报告在途操作；越权被拒绝；身份、原因和预算可审计 |
| ACC-11 | 事件重复、乱序并模拟游标过期；运行中升级能力包 | 不错误推进；报告缺口并恢复快照；原运行依赖不被静默替换 |
| ACC-12 | 测试环境模拟部分发布成功或分区写入后失败，按预定方案执行恢复；再注入一次补偿失败 | 分别核实代码版本和数据恢复结果；已成功及未恢复范围可查；补偿失败不能标记已恢复 |
| ACC-13 | 按约定备份恢复事项与工作流；目标平台保留备份后已受理的操作 | 先核实缺失或在途外部动作再开放后续写入；不能因本地记录回退就重复发布；保留恢复耗时和数据缺口证据 |

所有场景均保存执行输入、故障注入位置、预期与实际结果、相关 ID 和证据链接。能力缺失应登记为缺口，不以人工后台修正后的最终截图代替自动恢复证据。
