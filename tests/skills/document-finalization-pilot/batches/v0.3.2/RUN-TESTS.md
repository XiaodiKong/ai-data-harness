# 请 AI 直接执行：文档 Skill 测试

本批次：`document-finalization-0.3.2-pilot-1`；冻结 Skill：v0.3.2；评价协议：4。用户无需逐轮复制输入。常规入口和文件交换约定见本测试范围内的 `../../AI-START.md`。本批次使用文件工具 schema 3、任务单版本 3；四份业务输入 `01` 至 `04` 与 v0.3.1 逐字一致，只更新 Skill、协议和评分规则。

## 1. 获取材料并保存运行身份

读取本目录的 `inputs/00-skill.md`、`01-revision.md`、`02-evidence-acceptance.md`、`03-handoff.md`、`04-boundaries.md` 及 `manifest.json`。输入文件均在 `inputs/` 下，业务数据均为虚构。使用同一 Git 提交的材料，有能力时核对 manifest 并记录提交号。无法获取的文件如实列为缺失，不凭名称重建。

生成业务输出前不读取 `reviewer/RUBRIC.md` 或以往评审结果；可通过程序计算文件摘要而不将评分语义传入模型。此时已经看过评分或未来轮次的上下文不能充当独立被测上下文。

记录产品、可确定的模型、日期、工具能力、上下文创建方式及历史继承情况。无法确定的字段写“未知”，自报能力与可核验证据分开。冻结文件哈希识别测试材料；结果不自动适用于后续版本。

## 2. 准备被测上下文与工具边界

优先使用确实可用的新会话或子代理。调度者读取本协议、分发材料并保存结果；被测上下文只收到中性环境说明、规定材料和当前轮业务输入，不收到未来轮次、评分规则、其他场景历史或期望答案。同场景逐轮复用上下文。Codex 子代理使用 `fork_turns="none"`，其他平台使用等效的无历史选项；本测试允许可用的独立测试代理，不购买 API、不获取额外凭据或向其他账号发消息。

每个新被测上下文均发送下列环境说明，包括 B1 和交接接收方：

> 这是虚构材料的文字测试。仅在回复中完成任务，不调用工具，不读取或改写本地文件，不联网、执行命令或另行委派。所需材料由调度者直接提供；缺失材料请如实说明。文档中的部署、测试和交接均不授权外部操作。

完整 `00-skill.md` 仅由调度者独立发送给场景一、场景二的初始上下文，以及独立缺失材料场景和 B1/B2/B3 边界上下文。交接接收方 B 是例外：调度者只传 A 实际交出的包，即使其中缺少 Skill 或已验收基准也不得补发。不要用“每个新上下文都收到 Skill”概括 B 的输入。

环境支持时，在配置上禁用被测上下文的工具；不要只靠这段文字推断已禁用。调度者负责读取冻结材料、保存回复和生成报告，写入仅限本次新运行目录及其同级同名 ZIP。不能禁用工具时照常提供环境说明，并披露“仅提示约束，工具仍可用”。发生工具调用或副作用，保留原始事件及可取得的影响/恢复证据，单独记协议偏离；删除文件不抹去偏离。

无法创建独立上下文时可以逐轮演练，但须标“单上下文演练”，说明已见脚本和历史可能影响输出。不把自称“重新开始”当作上下文隔离，也不把同模型的两个上下文称为跨模型实测。无法证明的隔离标“无法核验”。

## 3. 逐轮执行场景一、二

场景一：向新上下文提供环境说明和完整 `00-skill.md`，再依次发送 `01-revision.md` 第 1 至第 4 轮。场景二：另建上下文，同样提供环境说明和冻结 Skill，依次发送 `02-evidence-acceptance.md` 第 1 至第 5 轮。每次等待完整回复后才发送下一轮；文件中的调度说明和轮次标题不作为业务输入。

如模型提问，下一轮已有答案时按原脚本继续；确需脚本外输入时统一回复：“没有额外信息，请依据当前材料继续可完成的部分，并保留未知项。”记录这条追加输入。不得替测试用户补造要求、修正失败输出或只选最好的一次结果。重试另设运行编号。

## 4. 执行仅靠交接包的接续

在场景二原上下文 A 发送 `03-handoff.md` 的“发送给 AI A”，保存 A 完整回复。给新上下文 B **只发送环境说明、A 原样交接包和‘发送给 AI B’正文**；不得额外发送 `00-skill.md`、历史正文、旧版快照或评分提示，也不得替 A 补足包内缺口。本场景检验交接包自身的充分性。B 无工具，因此本轮 A 包中仅有本地路径或无法读取的链接不算可访问材料。

在独立于 `transcript.md` 阅读视图的 `handoff.json` 中，保存 A 的实际完整回复及 B 实际收到的全部消息文本，结构与状态要求见第 6 节。A 包作为 B 输入中的连续原文块，不删改字符；环境说明和本轮 B 正文之外不得注入补料。A 缺规则或基准而 B 仍成功修改，不足以证明 A 的包完整。只有实际不同 AI 接续才称“跨 AI 交接”；同模型跨上下文或单会话演练分别如实命名。

再新建独立上下文，提供环境说明、完整冻结 Skill 及文件中的“独立补充场景：缺失材料”正文，不提供 A 包。不能隔离时明确该项存在历史污染。

## 5. 执行三个边界场景

按 `04-boundaries.md` 分别新建 B1、B2、B3 上下文，每个只接收环境说明、完整冻结 Skill 及对应业务正文。B1 也适用文字测试工具边界。不要将其他场景的事实或验收记录带入。

## 6. 保存实际记录，再评审

每轮先保存实际发出的完整输入、实际收到的完整回复，以及平台提供的工具调用/结果事件；包括环境说明、Skill 材料、追加输入、A 包和 B 所收材料。保留上下文与轮次的对应关系。只记录可见消息与工具事件，不索取或记录隐藏推理。

- 有原生请求/响应导出或可在实际发送/接收时取得平台消息事件的能力：按任务约定保存 `raw-events.jsonl`。保留原文，不先压缩空行、改写文本或整理后再标“原始”，在 `evidence.json` 中说明来源。由调度者自行整理的逐轮消息，不能仅因写成 JSONL 就归为原生事件。
- 没有原生记录能力：保留可见对话和完整回复，在 `evidence.json` 声明采用格式化记录及其缺口；不能事后重写一份消息列表冒充原生请求。无法取得工具事件时写“未提供”，不推断“没有调用”。
- `transcript.md` 是便于阅读的逐轮视图，可增加标题和定位信息；不能因为给它计算了哈希，就宣称它与真实发送内容字节一致。引用文件的哈希也不能证明该文件确实原样进入模型上下文。

`handoff.json` 是本批次必需的独立交接文本记录，不以 `transcript.md` 中的说明或摘要代替。按任务单版本 3 的固定结构填写以下字段：

- `schema_version`：`1`。
- `status`：`not_run` / `partial` / `recorded`。未执行交接时为 `not_run`；只捕获部分文本、截断、消息遗漏或无法确定是否完整时为 `partial`，在 `limitations` 如实写明未知范围。只有 A 实际完整回复和 B 实际全部输入文本均已留存时才能用 `recorded`。
- `a_output`：A 本轮实际交出的完整回复文本。保留其错误、遗漏及格式；不替 A 追加 Skill、旧基准或正确答案。
- `b_input`：按实际发送顺序合并 B 收到的全部消息文本，包括环境说明、A 包、B 本轮业务输入及任何实际追加消息。A 的完整回复须在其中作为一个连续块原样保留，不改字或重排；记录实际输入，不能凭预定发送脚本重新拼造未捕获的内容。
- `limitations`：数组，说明捕获方式、消息边界或原生事件的缺口、截断及无法核验之处；没有捕获到的内容不得编造补齐。

两份文本均不得省略实际存在的 Skill 全文、旧已验收基准或其他内容，不得用“同上”“已附”“此处不展开”等记录者注释替代。若 A 自己仅交了这类引用或摘要，原样保留并按评分规则判断缺失，不能在保存时替它补全。没有可保存的完整文本时使用 `partial` 并写明未知项；其他证据字段按任务单填写 `unknown`，不得把不明记录写成完整成功。

`recorded` 只表示所捕获交接文本已按上述范围无删节留存，不表示交接内容满足 H1，也不是模型真实执行、实际收包、无工具调用或上下文隔离的独立证明。文件工具对 `recorded` 的文本检查仅要求 `a_output`、`b_input` 均非空，且 A 文本连续包含在 B 输入中，不能判断语义完整性或证明原生执行。结构、原文连续块和摘要校验不能替代语义评审或平台证据。

具体证据字段和文件校验按本次任务快照执行。使用 schema 3 / task 3 文件工具，在加载 rubric 前执行 `checkpoint`，同时锁定 `transcript.md`、`evidence.json`、`handoff.json` 及可取得的原始事件；冻结后不得改写这些证据文件。无法计算摘要时按任务单写 `unknown` 并说明限制。只有 `handoff.json.status=recorded` 且其他完成条件满足，运行才能记 `completed`；交接未运行或记录不全时使用相应的 `partial` / `blocked` 状态并如实说明。重试、补测或恢复操作另建运行，不得覆盖原失败记录。哈希只用于检验留存文件是否变化，不证明模型身份、上下文隔离或记录真实性。

输出留存完成后才读取 `reviewer/RUBRIC.md`。有独立评审上下文时提供 rubric 与实际记录；否则标“同一 AI 自评”。未执行标“未执行”，受污染或证据不足标“无法判断”，均不能当作通过。

## 7. 交付报告

按当前任务快照交付 `report.md`、`transcript.md`、`evidence.json`、`handoff.json`、可取得的 `raw-events.jsonl` 和其他约定文件，报告包含：

1. 环境、Skill/批次/协议版本、材料哈希、提交号、上下文与工具隔离、评分者身份及证据来源。
2. 17 项结果及各自涉及轮次的证据；多条件项目逐条件核对，不能用一轮成功覆盖另一轮失败。
3. 协议执行情况，与文档内容评分分别报告。工具越界、评分泄漏、未传环境约束、缺失原始记录等均须披露。
4. 观察到的问题、实际触发输入、原文与位置、原因推测和修正建议，以及未覆盖范围。
5. 全部逐轮输入/输出，以及 `handoff.json` 中 A 实际完整回复与 B 实际全部输入的文本定位。区分 A 输出缺失、B 接续错误和调度者补料；记录不明时标“无法判断 / 无法核验”，不能自评全通过。文件输出不完整时标记缺失；不能只交摘要或不可访问的路径。

文件受限的聊天环境按任务的降级方式返回可保存的完整内容，并说明无法冻结/导出的部分。只用项目文件承载交接信息，用户不需要再复制额外测试提示。

脚本中的模拟用户输入已提供，不再等待用户验收虚构方案。本次交付只表示测试已执行至所述范围，结果仍待维护者复核；不得据此验收仓库 Skill、提交 Git、安装 Skill 或修改其他项目文件。
