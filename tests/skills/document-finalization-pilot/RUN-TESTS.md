# 请 AI 直接执行：文档 Skill 测试

用户只需把本文件的 GitHub 链接交给一个新 AI，并说“请读取这份说明，按步骤执行测试，最后给我完整报告”。无需用户逐轮复制测试输入。

## 执行目标

测试本仓库的 document-finalization v0.2.0 在当前 AI 环境中的实际表现。完成下面的场景，保留每轮输出，再评审。不要仅解释如何测试，也不要修改 Skill 后再测试。所有业务材料均为虚构测试数据。

## 1. 获取材料

读取本目录下的文件：

- `inputs/00-skill.md`：本次冻结的 Skill。
- `inputs/01-revision.md`：多轮修改场景。
- `inputs/02-evidence-acceptance.md`：证据与验收场景。
- `inputs/03-handoff.md`：交接及缺失材料场景。
- `manifest.json`：输入文件校验值。有文件工具时检查，不能检查则如实记录。

使用同一个 Git 提交中的材料，有能力时记录提交号。若无法访问 GitHub，明确说明缺失的文件并请求用户上传这些文件；不得凭文件名编造内容或声称已执行。获取材料时可以使用网络，生成业务方案时仅使用测试材料，不检索虚构业务的外部证据。

此时不要读取 `reviewer/RUBRIC.md`，也不要读仓库其他评估说明。先生成并保留实际结果，完成后才加载评分规则。

## 2. 确定执行模式

优先使用你当前环境确实支持的独立会话或子代理。此测试请求授权使用可用的独立测试代理，不要求用户另行逐轮操作。不要自行购买 API、获取凭据或向其他账号发送消息。

- **独立上下文执行**：你担任调度者。每个场景交给新的被测上下文，只提供冻结 Skill 和当前轮正文；等待回复后才发送下一轮，不提供未来轮次、评审规则或调度说明。保持同一场景各轮的上下文。
- **单上下文演练**：无法创建独立上下文时，你在当前会话按轮处理，完整输出每轮结果；场景之间仅使用对应输入重新开始。必须声明同一上下文无法真正隔离，提前可见的脚本和历史可能影响结果。这是演练，不得称为独立多轮实测或真正跨 AI 交接。

记录产品、可确定的模型名称、日期、工具能力、执行模式；无法确定的字段写“未知”。不要为了填写报告猜测型号。不得把本测试中的虚构验收解释为用户对仓库 Skill 的验收。

## 3. 执行场景一

依次执行 `01-revision.md` 的第 1 至第 4 轮。每轮记录实际输入与完整输出。文件顶部操作说明不作为被测任务输入。

不要用“模型应该……”代替真正生成该轮文档或回复。不要修改原始输入来帮助模型通过，也不要挑选最好的一次输出。

## 4. 执行场景二

在新的独立上下文执行 `02-evidence-acceptance.md` 的第 1 至第 5 轮；不支持独立上下文时标为演练，保留完整逐轮结果。

若被测 AI 提问，下一轮已有答案就按原脚本继续。确实需要额外输入且脚本没有时，统一回复：“没有额外信息，请依据当前材料继续可完成的部分，并保留未知项。”记录该额外输入。不要擅自编造测试用户的补充信息。

## 5. 执行交接场景

向场景二的原上下文发送 `03-handoff.md` 中“发送给 AI A”的内容，保留完整交接包。然后将冻结 Skill、交接包和“发送给 AI B”的内容发送到新上下文，生成接续结果。不转发原始场景历史，不修补交接包。

若接收方实际仍是同一模型，只称“同模型跨上下文交接”；若在同一会话内模拟，只称“交接演练”。只有确实由不同 AI 接续才能称“跨 AI 交接”，记录双方身份和实际传递材料。不具备该条件不影响完成本轮其他测试。

再用新的上下文执行文件中的“独立补充场景：缺失材料”，只提供冻结 Skill 和该段输入，不能提供完整交接包。不支持隔离时明确记录该项受到已有历史污染，独立行为无法验证。

## 6. 保留结果后评审

完成输出后，读取 `reviewer/RUBRIC.md`，逐项对照实际内容评分。先保存原始结果，再评审；评分后不要回写或美化原始回复。

有独立评审上下文时，给评审者评分规则与原始结果；否则标记“同一 AI 自评”。没有完成的项标“未执行”；因上下文污染无法确认的项标“无法判断”，不要自动判通过。

## 7. 交付报告

报告必须包含：

1. 环境与范围：日期、AI/模型、Skill 版本、提交号（若可得）、执行模式、上下文隔离情况、评分者是否独立。
2. 测试结果：每项编号、通过/部分通过/失败/未执行/无法判断、对应场景和轮次、简短原文证据。
3. 发现的问题：实际触发输入、输出证据、可能原因、建议修正；区分观察事实与原因推测。
4. 覆盖限制：哪些结论只是演练、哪些真正独立执行，是否真的跨模型交接。
5. 原始记录：全部输入、逐轮完整回复、交接包。支持文件时输出 `report.md` 和 `transcript.md`；否则在聊天分区输出，避免只给无法访问的本地路径。

如果输出长度有限，优先落盘或提供可下载文件；做不到时分批输出，并明确哪些尚未输出。不能用摘要冒充完整原始记录。

不用请求用户验收这些虚构方案，也不用等待用户逐轮确认；脚本里的模拟用户输入已提供。最终只提交测试报告，实际结果仍待项目维护者复核。不要修改仓库、提交 Git 或安装 Skill。
