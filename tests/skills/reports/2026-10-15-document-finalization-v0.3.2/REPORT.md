## 本轮修订

| 实际问题 | v0.3.2 的处理 |
| --- | --- |
| 删除实时流程后，没有补每日增量流程 | 要求提供本次交付深度所需的替代流程；未知实现细节保留条件，不把整个流程留空。 |
| 缺预算时标题“待验收”、结尾“对焦中” | 先判定状态，再同步标题、摘要、状态栏、交付及交接记录；保留历史版本原状态。 |
| 非阻塞项又被泛称为进入验收前必须澄清 | 每个阻塞对应已有标准及影响，不用笼统“全部确认后”抬高门槛。 |
| 用“其余相同”替代完整旧基准，声明“已附全文”代替材料核对 | 交接前逐项定位实际内容；模板给出两份短版完整正文的正例，强调长文同样不能省略。 |
| A 包中 Skill 被省略，B 输入仅通过引用描述，无法恢复实际传递内容 | 新运行单独保存 handoff.json，锁定并打包 A 完整输出与 B 全部实际输入；不由调度者补料。 |
| 内容自评和证据核验过度乐观 | 逐条件评 R1/E1/H1/H4，缺失与无法判断分开，未知协议条件不汇总为“符合”。 |

新运行采用文件 schema/task 3。旧 schema 1/2 保持可校验和打包。四份业务输入与 v0.3.1 逐字一致；Skill、协议和评分规则已变化，比较时仍须说明条件差异。原始运行和旧冻结批次没有改写。
