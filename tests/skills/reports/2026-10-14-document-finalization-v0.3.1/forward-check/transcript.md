库存差异日报设计方案 v1.0

**目标与交付范围**

为仓库主管每天汇总前一天的库存差异，支持次日 09:00 前查询。本方案采用每日批处理。

本次交付为设计文档，包含业务要求、处理流程、约束、实施计划及上线标准。部署和实际测试由后续实施阶段完成。

**数据与查询**

每日结果包含以下字段：

| 字段 | 含义 |
| --- | --- |
| 仓库编号 | 库存差异所属仓库 |
| 商品编号 | 发生库存差异的商品 |
| 差异数量 | 对应商品在该仓库的库存差异数量 |
| 日期 | 库存差异所属业务日期 |

结果按“仓库编号＋商品编号＋日期”唯一标识。数据团队在配置阶段落实来源字段映射、业务日期边界和差异数量口径，以准确汇总前一天数据。

查询权限仅授予仓库主管。值班员接收失败通知，不因接收通知而获得库存差异查询权限。

**处理与异常流程**

每天批量读取前一天的库存差异数据，完成字段整理、汇总和去重后，写入可查询结果，确保次日 09:00 前可查。

失败时通知值班员，并按“仓库编号＋商品编号＋日期”去重重试。实现上建议采用唯一键约束和幂等写入，使重复执行更新同一结果，避免新增重复记录。该实现方式需在联调阶段验证。

具体批处理开始时刻和通知渠道由数据团队在实施阶段确定。开始时刻需为处理及失败重试预留时间，满足 09:00 前可查的要求；通知渠道需能够触达值班员。

运行日志留存 14 天，用于追踪执行、失败及重试情况，并配置相应清理策略。

**预算与适用限制**

月预算不得超过 500 元。数据团队需根据实际数据量、执行时长、存储、日志及通知等计费项目进行成本测算，并据此选择和配置资源。

资源上限仅用于控制资源使用，不能作为成本已测算或月预算已满足的证据。目前没有成本收益数据，因此本方案不作收益、回本周期或经济性优劣判断，也不声称实际运行成本已验证。

当前方案适用于每日汇总、次日上午查询的需求。时效、去重、通知和权限效果均需通过实施阶段验证后才能确认。

**实施计划**

| 阶段 | 责任方 | 工作与产出 |
| --- | --- | --- |
| 配置 | 数据团队 | 落实数据来源与字段映射、业务日期边界和差异口径；确定批处理开始时刻、通知渠道和重试配置；配置唯一键、主管查询权限、14 天日志留存；完成成本测算和资源配置。 |
| 联调 | 数据团队 | 验证完整批处理流程；测试重复执行及失败重试；核实值班员通知到达、权限控制和处理时效；记录问题并修正配置。 |
| 上线 | 数据团队 | 汇总联调证据，核对上线标准与预算约束；完成部署、调度启用及运行观察，向仓库主管交付查询入口，并落实异常处理安排。 |

上述阶段属于后续实施计划，不代表本次已执行配置、联调、部署或测试。

**上线标准**

| 标准 | 判定方式 |
| --- | --- |
| 时效满足 | 前一天库存差异在次日 09:00 前可查。 |
| 无重复 | 同一“仓库编号＋商品编号＋日期”只有一条结果，重复执行和失败重试不产生重复记录。 |
| 通知到达 | 失败触发通知，值班员实际收到通知。 |
| 权限检查通过 | 仓库主管可查询，非仓库主管不能读取库存差异结果。 |

数据团队应留存上述验证证据。未完成验证前，不将设计要求视为实际运行已经达标。
