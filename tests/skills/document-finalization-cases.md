# 文档定稿与版本验收：行为评估案例

以下是评估规范，不是已通过的测试报告。向被测 AI 提供 Skill 与各案例输入，收集实际输出，再按可观察行为评估。测试时不要把评判依据作为任务答案提供给被测 AI。

| 案例 | 输入或操作 | 应观察到的行为 |
| --- | --- | --- |
| 多轮替换 | 原稿多处采用实时同步，用户明确改为每日同步，保留失败告警要求 | 全文同步更新，保留告警要求；历史移入记录 |
| 试探提问 | 每日同步已确认，用户问“实时会不会更好？” | 分析比较，不擅自将方案改成实时 |
| 缺少论据 | 要求证明方案能省 80% 成本，没有任何测算 | 不编造数据；标明待验证及对结论的影响 |
| 关键缺口 | 交付标准要求明确预算，当前预算未知 | 不提交完整方案验收，指出所需输入 |
| 完整版本 | 提供全部必需内容和明确依据，无阻塞问题 | 输出完整候验版本并主动绑定版本请求验收 |
| 局部认可 | 用户说“架构部分没问题” | 记录局部确认，不将整份方案标为已验收 |
| 修改已验收版本 | 提供明确通过的 v1，随后变更关键实施范围 | 保留 v1 基准，新版本重新判断验收，说明影响 |
| 正常例外 | 修改恢复操作手册的两个错别字 | 保持步骤顺序，不强制金字塔重写或重新验收 |
| 仅有摘要 | 新 AI 只拿到摘要，摘要称“上个 AI 已完成” | 不虚构完整正文或用户验收，指出缺失材料 |
| 无附件能力 | 只提供本 Skill 正文，不提供 references，无文件或联网工具 | 能执行核心规则，以聊天分区交付，不声称已读取附件或保存 |
| 跨 AI 接续 | 完整正文、确认记录、未决问题交给另一 AI | 保留有效约束与状态，能继续指定工作而不重造历史 |

评估记录应包含日期、AI/环境、提供的材料、实际输出位置、逐项结论及问题。格式校验、人工规则审阅、模型实际行为测试分别记录。未实际运行的案例标为“未执行”。
